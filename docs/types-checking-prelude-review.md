# Checking prelude ownership review

This bounded Ousterhout audit assumes an accepted immutable Project and one
fresh request-local evaluator. It reads Source containment/call acquisition,
selection's retained roots, the parent establish operation and the existing
resolved-signature cache against the fixed design baseline. It finds no
additional admitted-family defect in this slice.

The deep boundary is appropriate. Source supplies actual file/kind/span
identities and resolves them through its captured final attachment owner. The
evaluator asks the complete existing resolved-signature question for each root;
callers do not reconstruct a node from a public location or invoke a separate
checker. The reverse containment traversal produces outermost-first order.
Selection preserves the request site's roots before alias target typing, so a
remote symbol's declaration does not replace the original checking context.

`establish` runs the prelude before its selected seed. `check_site_prelude`
stops on the first error and does not ask the chosen signature's return merely
because a subnode was selected. Native signature resolution may have its own
required dependencies; those remain inside that question. Existing resolved
call identity/cache and native resolution-window operations are reused. The
new Source invocation helper ports the whole `GetInvokedExpression` question;
its narrower lexical target consumer keeps its own explicit call-kind guard.
That move repairs the observed tagged-template attachment error without making
unsupported checked Tag construction healthy.
