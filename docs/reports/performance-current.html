01 / READ THE CHARTS

Three different states

Cold and warm identify the project service state. They do not give the temperature of the computer.

COLD

The service process has no project data. The first request reads, parses, resolves, and binds the project.

WARM

The service has the project. Each request checks the files and prepares an answer. The service can do these two tasks at the same time.

AFTER AN EDIT

A file has changed. The service builds a new project. It can use unchanged source text, indexes, facts, and resolution results again.

The operating system file cache was not cleared. Cold requests do not include service process startup. Each measured request includes its client process.

CPU speed limit

Scroll sideways to see the full chart.

  • Project operations use two new services for each case. Each service has one cold request, then five warm requests.
  • Each service receives two warm member requests. Member search and type expansion results are partial, with exit code 1.
  • Cold and warm output bytes are the same for each operation. The service stays at generation 1 during each command case.
  • Edit preparation makes a diff. Apply tests change disposable file copies. Refresh tests change one file in the project copy, then put the initial bytes back.
  • The stack profiles and the time measurements use different service runs. Stack profiles add measurement work.
  • The 20 ms memory traces can miss short peaks. The peak bars use the operating system interval peak.
  • These tests do not measure a cleared disk cache, service auto-start, each selector, or each type expansion.
  • The first type expansion setup test gave a partial result. The harness only permitted exit 0 for that test. The time series does not include this setup test.
  • Service status is a control operation. It does not read or bind the project.
