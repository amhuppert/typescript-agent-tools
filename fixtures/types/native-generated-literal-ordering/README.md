# Native literal ordering

Each marked expression is a final contextual parameter query. A tuple retains
the actual identity spelling beside the union being observed, so the harness
can verify ordering without assuming a compiler-process ID. The two nested
class cases retain both identities in that same query. Captured IDs and native
summaries are evidence; Rust output uses symbolic identities with their own
actual declaration origins.

The matrix follows `CompareTypes`' byte comparison: equal atoms with different
suffixes, a whole-atom prefix, repeated atoms, a decisive fixed prefix, empty,
NUL, `0`, `:` and both insertion orders. Every possible positive first digit
has a separate spelling-dependent control. Unequal atoms and different adjacent
partitions stay explicit dependencies in the product even when this native
run can order its concrete IDs. An abstract-template union is consumed by a
conditional yielding the ordinary string `ordered`, exercising text-span order
without requiring symbolic abstract-template presentation.

`uniqueCycle` and its reversed insertion order reconstruct raw `FE@a@ID`,
`FE@a0@ID`, and composed `FE@a9ID`. Their literal order must be the byte order
`a0`, `a9`, `a@`; the separate property-key underlying-name policy cannot be
mixed into it. `rawFE` keeps native raw FE distinct from source U+FFFD despite
the former's escaped display.

The harness compares the pinned compiler hook and public API, checks semantic
diagnostics and demand failures, records the API declaration origins and exact
summary, then replays maintained strict/loose baselines. No Rust behavior is
used to choose the expected native order.
