# Native generated literal context and ID width

Independent reachability probes for the exact native literal value design.
Every row compares a fresh API answer with the same-checker hook. The context
configs include only cases.ts; cold/warm width configs each include only their
own source, so other private declarations cannot alter those controls.

Contextual static property checking uses raw Symbol.Name in checker29369,
then generic mapped substitution at30364. Public static and private instance
controls distinguish the two gates. Identity extraction/head, concatenation,
and all four casing operations probe whether raw generated strings can escape
through contextual parameter types. keyof/mapped controls ask separate native
public-name operations and do not assert private-name visibility.

The width pair asks the same private access and template index signatures.
Nine preceding private classes force additional native symbol-ID acquisition.
The split template's empty delimiter can consume the first decimal digit while
the following numeric placeholder validates the rest. This is deliberately a
native-history probe, not a proposed product decimal-ID representation.

Captured raw summaries may include native process IDs; they establish native
reachability only. Product identity/output policy must not copy those digits.
No shared hook edits or extra semantic acquisitions are added.
