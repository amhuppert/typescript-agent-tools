# Native diagnostic node cache

These are natural checked call/equality queries in one checker. The optional
`inspectDiagnosticCache` observer records existing node-builder decisions and
raw fields without asking for additional types, symbols or native IDs. Calls in
a comma expression warm the same checker; distinct Project requests do not
establish warm-cache behavior. Diagnostic code arrays are source sorted and do
not establish acquisition order. The ordered node-builder events do.

All 14 roots in three profiles passed in
`vrun-b378df78-f55a-4fb1-805c-485f363d1429`. The hooked final type/errorType
matches the unmodified native API. Event assertions check installation and key
identity before a hit, length/truncation/tracked-symbol replay and miss cleanup.
Natural cases establish cold/warm nonnil scopes, distinct scopes, recovered
child display, equal-byte qualification and native truncation/noErrorTruncation.

The `this` instance cases prove tracked-symbol replay. The names
`reportedCold`/`reportedWarm` are candidate labels only: their nested `this`
annotation produces TS2526, and neither sets the builder's reportedDiagnostic
flag. They do not prove reporter veto. The recursive case likewise does not
reach depth elision. Those two boundary witnesses remain required. Final
Project tests must retain the actual declaration-serialization dependency until
its pseudochecker owner is complete; a native successful summary is not evidence
that the product may ignore consumed recovery.
