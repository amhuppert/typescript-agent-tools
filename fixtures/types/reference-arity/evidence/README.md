# Native reference argument controls

These disposable fresh TypeScript 7.0.2 API sessions query
`GetTypeAtLocation` on the actual `TypeReference` node. They use `noLib: true`
with a single captured TypeScript source; none invokes a whole-file semantic
diagnostic prelude. Each result retains native root flags, native error-type
predicate, actual ordered argument flags, and the input diagnostic inventory.

`answers.json` contains six count/default controls and `answers-extra.json`
contains twelve order, canonical default-substitution and recovery controls.
`answers-alias-context.json` preserves the earlier direct-alias question:
healthy generic references carry the alias's native printed identity, while
bad arity still returns errorType. That distinct context is not proof that a
target-and-arguments interner can implement aliased references.

The scripts are byte-preserved from `.cc/temp/types-reference-arity`; their
relative import and scratch input paths name their original measurement
environment. The copied source bytes were checked against every answer's
actual API SourceFile text. Config and tooling-owner hashes were recorded after
the probes. This is bounded compiler research, not a complete atomic hook input
capture or a registered product test. The earlier alias-context inputs were
subsequently reused; those original sources are preserved inline in the answer
artifact rather than misrepresented by the later input copies.

The manifest excludes this explanatory README intentionally. It binds the
saved control scripts, observations and input copies; it does not assert
semantic completion, performance, generic recursion, alias instantiation or
resource-gate closure.
