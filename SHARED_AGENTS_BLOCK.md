## TypeScript Navigation, Queries, and Editing (`tsparse`)

Use `tsparse` (and load the `tsparse` skill) as your primary workflow for reading, searching, analyzing, and editing TypeScript/TSX code—before reaching for `rg`/`grep` or reading whole files. `tsparse` understands TypeScript 7 syntax, scopes, import/export aliases, and receiver types, and reuses a warm background project service; latency depends on project size and machine load. Using it instead of raw file reads and text searches saves time, context tokens, and cost while avoiding false-positive text matches.

- **Skill:** Load the `tsparse` skill whenever navigating unfamiliar TypeScript modules, finding where a name is declared, tracing symbol/member references or types, or performing structured code edits.
- **Help:** Run `tsparse --help` for the operation index, or `tsparse --<op> --help` (e.g., `tsparse --references --help`, `tsparse --edit-batch EDITS --help`) for an operation's flags, examples, and exit codes.
- **Service runtime directory:** Project queries reuse a background service whose private directory is `TSPARSE_SERVICE_DIR` when set, else `$TMPDIR/tsparse-UID` when `TMPDIR` is absolute and short enough, else `/tmp/tsparse-UID`. In a sandbox where `/tmp` is not writable, set `TMPDIR` or `TSPARSE_SERVICE_DIR` to a writable directory. Directory creation/inspection and lock failures (exit 2) name these remedies and explain why `TMPDIR` was skipped; privacy failures instead name a permission or ownership remedy, such as `chmod 700`. A passing doctor metadata check does not prove lock writability.
- **Platform and inputs:** `tsparse` builds and runs on macOS and Linux only. Project loading reads only regular files: a source, `tsconfig.json`, or `package.json` that is a pipe, device, or socket is refused with `PATH: not a regular file` (exit 2).
- **Duplicate packages:** A package installed more than once with the same name, version, and installed peers is one program input, as TypeScript makes it; a request naming the other copy's file fails (`Unsupported`, exit 1) and names the file to query instead.
- **Compiler compatibility:** The nearest `node_modules/typescript/package.json` above the configuration selects TypeScript 5.6 rules for any 5.x version (only 5.6.3 is validated), or TypeScript 7 otherwise; TypeScript 7.0.2 remains the semantic authority. Under the 5.6 dialect, unknown options, enabled removed settings and invalid library names are `Config` failures (exit 1); unsupported settings or defaults such as ES5, classic/node10 resolution, or false `alwaysStrict` are `Unsupported` (exit 1), naming the option to correct. Read the error and the skill's full compatibility limits before changing configuration. Doctor reports the installed manifest/version, dialect, validation caveat and standard-library source.
- **JavaScript:** Under `allowJs`, plain ES module `.js`/`.jsx`/`.mjs`/`.cjs` files are analyzed like TypeScript, as is a CommonJS file whose one export is a top-level `module.exports = name;`, and a JSDoc `@type` on a variable (including `import("pkg").T`) is its declared type. Other CommonJS exports, `require`, expando assignments (`f.x = 1`), class `this.x =` members, and other JSDoc types and tags fail loading at the construct (`unsupported JavaScript: ...`, exit 1); use text search for such files. JavaScript is never edited.
- **Project semantics:** Definitions and construction queries share compiler selection, `baseUrl`/`paths`, JavaScript admission and package redirects with references and types. Import hints on a missed `--show --name` lead to `--definition` at the existing specifier.

### Operations
- `tsparse [FILE|-]` (`--check`, `--tsx`): Parse a file or stdin into a TypeScript 7 JSON AST, or pass `--check` to validate syntax only (it also rejects `module X {}` namespaces, TS1540, as TypeScript 7 does, and TypeScript-only syntax in a JavaScript file).
- `tsparse --outline FILE [--project TSCONFIG]`: List a file's declarations in source order with `LINE:COLUMN`, kind, and one-line signature.
- `tsparse --test-outline FILE`: List a TypeScript or JavaScript test file's `describe`/`it`/`test` calls and hooks in source order, indented by containment, with each test's name; each listed `LINE:COLUMN` selects that test's statement for `--show --at` and, for TypeScript targets, `--insert-after --at`.
- `tsparse --show (--name NAME | --at [FILE:]LINE:COLUMN) [FILE] [--project TSCONFIG]`: Print one declaration's exact source with original line numbers; where no declaration is named or anchored at the position, `--at` on a statement's first token prints that statement.
- `tsparse --type --project TSCONFIG (--name NAME | --at [FILE:]LINE:COLUMN) [--expand]`: Inspect the resolved type (and optional structural graph) of a declaration or token; a type name, including a one-name `import("…")` type, reports its whole type, and an import type TypeScript rejects is a located failure, not `any`.
- `tsparse --references --project TSCONFIG (--name NAME | --at [FILE:]LINE:COLUMN) [--calls] [--no-tests] [--file FILE]`: Group all declarations and uses of a symbol or `Receiver.member` across a project.
- `tsparse --definition --project TSCONFIG (--name NAME [FILE] | --at [FILE:]LINE:COLUMN)`: Print where an imported, re-exported, or used name is declared, following import/export aliases and barrel re-exports to the original declarations; a member position exits `1` with the `--references` command that finds its declarations.
- `tsparse --constructs --project TSCONFIG (--name NAME | --at [FILE:]LINE:COLUMN) [--missing KEY] [--all-literals] [--no-tests] [--file FILE]`: List the object literals that construct an interface, class, or type alias, and the properties (optional ones too) each does not certainly provide; by default it examines literals naming one of its keys or none, and `--all-literals` (much slower) examines every literal.
- `tsparse --replace-body (--name NAME | --at [FILE:]LINE:COLUMN) --from FRAGMENT [--plan PLAN]`: Preview replacing the body of a function, method, constructor, accessor, or arrow function.
- `tsparse --insert-after (--name NAME | --at [FILE:]LINE:COLUMN) --from FRAGMENT [--plan PLAN]`: Preview inserting complete statements after a selected declaration's statement, or after a statement-list statement whose first token is at `--at` where no declaration is named or anchored at the position (such as an `it(...)` test); a refused callback may name its enclosing statement's position.
- `tsparse --edit-batch EDITS [--project TSCONFIG] [--plan PLAN]`: Preview and validate multiple `replace_body` and `insert_after` edits together from a JSON file.
- `tsparse --apply PLAN`: Atomically write a saved `--plan` to disk after verifying every target file's original bytes and identity; replaced files keep only their permission mode (no extended attributes, ACLs, owner, or group).
- `tsparse --references-status --project TSCONFIG`: Report the state, PID, generation, idle time, and limits of the project's background service.
- `tsparse --references-stop --project TSCONFIG`: Stop the project's background service and release its cached snapshot.
- `tsparse --references-serve --project TSCONFIG`: Run the project's background service in the foreground until idle.
- `tsparse --doctor [--project TSCONFIG]`: Check build capabilities, `TSPARSE_*` environment variables, the runtime directory (which of `TSPARSE_SERVICE_DIR`, `$TMPDIR/tsparse-UID`, or `/tmp/tsparse-UID` was chosen and why) and its permissions, and service health; with `--project`, also the installed TypeScript compiler and the dialect it selects (a TypeScript 5.x project's configuration, module resolution including `baseUrl`, and its compiler's own standard libraries follow TypeScript 5.6.3's rules).

Do not work around `tsparse` problems silently. In your final response, surface any bugs, workflow friction, misleading diagnostics or remedies, stale/incorrect results, or missing capabilities/enhancements that forced you to fall back to text search or raw file reads—include the exact command run, its output, and what you needed instead.
